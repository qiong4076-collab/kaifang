# AI 订阅服务

中文人工订阅办理网站，参考同类站点的信息结构，使用独立品牌与服务内容。

## 已实现

- 首页、ChatGPT 套餐、Pro、教程、FAQ、指南、隐私说明、服务说明。
- 创建订单、个人收款二维码、客户提交付款信息、凭证查询与状态时间线。
- 后台登录、人工收款确认、状态流转、套餐价格、客服与二维码设置、CSV 导出。
- SQLite 服务端存储、服务端定价、查询凭证摘要、后台 HttpOnly 会话、来源检查与限流。

## 运行

需要 Node.js 24 或以上版本，无第三方 npm 依赖。

```powershell
$env:ADMIN_PASSWORD = '请替换为自己至少14个字符的管理密码'
$env:PUBLIC_ORIGIN = 'http://localhost:3000'
node server.mjs
```

浏览器打开 http://localhost:3000，后台位于 /admin。不要把实际管理密码写入仓库。

## 开售前配置

1. 后台设置品牌、客服联系方式、服务时间、退款说明。
2. 将自己的收款二维码图片加入 public/，例如 public/alipay.png，再填写 /alipay.png；也可填写可信 HTTPS 图片链接。
3. 设置每个套餐的实际人民币月费，并逐个开启商品。
4. 最后开启“开放客户下单”。默认没有价格和收款配置，网站不开售。
5. 用小额内部测试订单核对下单、付款信息提交、收款确认、处理和完成流程。

## 人工处理

客户提交付款信息不会自动确认收款。必须在支付宝或微信中核实到账后，后台标记已确认收款。已退款只记录状态，实际退款需要运营者自行执行。

本版本不接入充值上游、不自动登录客户账号、不收集客户密码或会话 Token。订阅办理由运营者沿用自己的现有人工渠道完成。

## 部署

Dockerfile 使用 Node.js 24。部署时设置 HOST=0.0.0.0、ADMIN_PASSWORD、PUBLIC_ORIGIN=https://你的域名，并将 /app/data 挂载到持久化磁盘。仅支持单实例 SQLite 部署；不要使用不持久化磁盘的静态托管或多实例部署。反向代理需提供 HTTPS。

个人收款、商品信息、售后与隐私内容需由运营者确认。没有厂商授权、统计数据或客户授权时，不使用官方合作、成功率、评价等承诺。

## 卡密自动发货

1. 在后台“卡密库存”按对应套餐导入，每行一张、每批最多 100 张。重复卡密跨套餐去重；列表只显示掩码。
2. 在套餐设置选择“卡密自动发货”，填写兑换入口、有效期、使用范围和售后说明，保存价格及开售状态。
3. 客户付款后，你核实真实到账，在订单处理中选择“已确认收款”。系统原子分配一张库存卡密并将订单完成；订单页展示卡密、复制按钮和购买时的兑换说明。
4. 缺货时订单保留为已收款待补货。导入库存后，点击该订单“补发卡密”。已完成订单重试不会再分配，已发卡密即使退款也不会回库。

付款核实仍为人工；通过订单页交付卡密，不发送邮件或微信消息，也不替买家在外部平台兑换。下单不预占卡密，待付款订单竞争最后一张库存时可能出现已付款待补货。交付方式与兑换说明保存订单快照，修改商品不影响已有订单。

卡密使用 AES-256-GCM 加密保存。CARD_ENCRYPTION_KEY 必须长期保留，不要直接替换，否则历史卡密将无法解密；CSV 不包含卡密。

独立版本需设置 CARD_ENCRYPTION_KEY 为自行生成的 32 字节随机密钥的十六进制字符串（64 字符），并与数据库一起妥善保管；不配置时人工模式可用，卡密导入与开售会被拒绝。不要把密钥写入 Git 或镜像。
